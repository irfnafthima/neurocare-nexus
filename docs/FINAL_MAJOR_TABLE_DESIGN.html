TABLE DESIGN

NeuroCare Nexus: Enterprise Database Design & Architectural Specification
NeuroCare Nexus uses PostgreSQL as its relational database management system. The database follows a relational design to support secure user management, patient clinical information, care-team authorization, physiological monitoring, doctor verification, alerts, communication, and AI-assisted healthcare functionality. Standard Django framework tables and synthetic testing registries are excluded from this core design specification.

A. Core User and Access Tables

TABLE 1: USERS (accounts_customuser)
Stores authentication credentials, role-based access classifications, account lifecycle states, and primary contact attributes.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the user account.
email VARCHAR(254) UNIQUE, NOT NULL Unique primary email address used for system login and communication.
password VARCHAR(128) NOT NULL PBKDF2/Argon2 cryptographic hash of the user password.
full_name VARCHAR(100) NOT NULL Full legal display name of the user.
role VARCHAR(50) NOT NULL Role categorization: patient, doctor, caregiver, family, admin.
phone VARCHAR(20) NULL Primary contact phone number.
approved BOOLEAN NOT NULL, DEFAULT: True Approval status (defaults to False for doctor role pending vetting).
status VARCHAR(20) NOT NULL, DEFAULT: 'ACTIVE' Account lifecycle status: PENDING, ACTIVE, or REJECTED.
specialization VARCHAR(100) NULL Medical specialty for doctor accounts (e.g., Neurologist, Physiatrist).
experience INTEGER NULL Total years of professional medical or caregiving experience.
bio TEXT NULL Professional biography, summary, or clinical background notes.
is_active BOOLEAN NOT NULL, DEFAULT: True Designates whether this account is currently active.
date_joined TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when the user account was registered.
TABLE 2: DOCTOR PROFILES (doctors_doctorprofile)
Stores verified professional profiles, statutory council registration credentials, qualifications, and verification states.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the doctor profile.
user_id BIGINT FK → accounts_customuser.id, UNIQUE, NOT NULL One-to-One link to the registered doctor User account.
medical_registration_number VARCHAR(50) NOT NULL Official medical registration number issued by statutory council.
state_medical_council VARCHAR(150) NOT NULL State medical council where practitioner is registered.
qualification VARCHAR(150) NOT NULL Primary recognized medical degrees (e.g., MBBS, MD, DM).
specialization VARCHAR(100) NOT NULL Clinical specialization focus area.
hpr_id VARCHAR(100) NULL National Healthcare Professional Registry (HPR / ABDM) ID.
years_of_experience INTEGER NOT NULL, DEFAULT: 0 Total cumulative years in active clinical practice.
verification_status VARCHAR(25) NOT NULL, DEFAULT: 'PENDING' Vetting state: PENDING, VERIFIED, REJECTED, SUSPENDED.
verified_at TIMESTAMP WITH TIME ZONE NULL Timestamp when the profile was officially approved.
TABLE 3: CAREGIVER PROFILES (caregivers_caregiverprofile)
Stores nursing credentials, agency affiliations, qualifications, and verification statuses for registered caregivers.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the caregiver profile.
user_id BIGINT FK → accounts_customuser.id, UNIQUE, NOT NULL One-to-One link to registered caregiver User account.
caregiver_type VARCHAR(20) NOT NULL, DEFAULT: 'PROFESSIONAL' Caregiver classification: PROFESSIONAL or FAMILY.
full_name VARCHAR(100) NOT NULL Complete legal name of the caregiver.
qualification VARCHAR(150) NULL Nursing accreditation or clinical training certification.
current_agency VARCHAR(150) NULL Name of employing healthcare or nursing agency.
verification_status VARCHAR(20) NOT NULL, DEFAULT: 'PENDING' Vetting state: PENDING, VERIFIED, REJECTED.
verified_at TIMESTAMP WITH TIME ZONE NULL Timestamp when the caregiver profile was verified.
TABLE 4: DOCTOR-PATIENT AUTHORIZATION LINKS (doctors_doctorpatientlink)
Maintains active authorized clinical relationships between doctors and patients, establishing clinical data access boundaries.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the linkage.
doctor_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing assigned doctor User account.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing the managed patient.
created_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when authorization link was established.
* Composite Unique Constraint: (patient_id, doctor_id)
TABLE 5: CAREGIVER-PATIENT AUTHORIZATION LINKS (caregivers_caregiverpatientlink)
Maintains authorized bedside caregiving assignments, access permissions, and read-only privilege restrictions.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the assignment link.
caregiver_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing caregiver User account.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing the assigned patient.
is_read_only BOOLEAN NOT NULL, DEFAULT: True Access restriction flag (prevents unauthorized record modifications).
is_approved BOOLEAN NOT NULL, DEFAULT: True Administrative approval status of the care assignment.
created_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when assignment link was created.
* Composite Unique Constraint: (caregiver_id, patient_id)
TABLE 6: FAMILY-PATIENT AUTHORIZATION LINKS (patients_familypatientlink)
Maintains verified family relationships, portal visibility authorization, and optional clinical record editing permissions.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the link.
family_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing family User account.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing linked patient.
is_approved BOOLEAN NOT NULL, DEFAULT: False Designates whether the link is approved by admin/doctor.
can_edit_clinical BOOLEAN NOT NULL, DEFAULT: False Privilege flag granting permission to add/edit clinical data.
created_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when relationship link was established.
* Composite Unique Constraint: (family_id, patient_id)
TABLE 7: DOCTOR CREDENTIAL VERIFICATION RECORDS (doctors_verificationrecord)
Logs automated and administrative credential verification audits, regulatory matching scores, and vetting decisions.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying verification log.
user_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing user account verified.
verification_type VARCHAR(30) NOT NULL Type: PROFESSIONAL_REGISTRATION, IDENTITY_MATCH, QUALIFICATION, ADMIN_REVIEW.
source VARCHAR(150) NOT NULL Regulatory registry endpoint or authority evaluated.
result VARCHAR(20) NOT NULL Outcome: EXACT_MATCH, LIKELY_MATCH, MISMATCH, MANUAL_REVIEW.
verified_by_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing reviewing administrator.
verified_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when verification step was performed.

B. Clinical and Patient Record Tables

TABLE 8: PATIENTS (patients_patient)
Stores core demographic, clinical baseline, neurological condition summary, risk score, and emergency contact details.
Field Name Data Type Constraints Description
id VARCHAR(20) PK, NOT NULL Unique business primary key identifying patient (e.g., P-102).
name VARCHAR(100) NOT NULL Full legal name of the patient.
age INTEGER NOT NULL Patient age in years.
gender VARCHAR(10) NOT NULL Patient gender (e.g., Male, Female, Other).
room VARCHAR(10) NOT NULL Hospital room or ward designation (e.g., 302A, ICU-4).
condition VARCHAR(255) NOT NULL Primary neurological diagnosis or condition summary.
risk INTEGER NOT NULL, DEFAULT: 0 Calculated baseline clinical risk index (0–100).
status VARCHAR(50) NOT NULL, DEFAULT: 'Normal' Status: Normal, Critical, Stable, Discharged.
ehr_notes TEXT NOT NULL, DEFAULT: '' Baseline electronic health record summary notes.
phone VARCHAR(25) NOT NULL, DEFAULT: '' Primary contact phone number.
emergency_contact_name VARCHAR(100) NOT NULL, DEFAULT: '' Full name of primary emergency contact.
emergency_contact_phone VARCHAR(25) NOT NULL, DEFAULT: '' Emergency contact telephone number.
blood_group VARCHAR(10) NOT NULL, DEFAULT: '' ABO/Rh blood group typing (e.g., A+, O-, B+).
TABLE 9: PATIENT CONDITIONS (medical_records_patientcondition)
Maintains structured tracking of a patient's chronic diagnoses, neurological conditions, comorbidities, and resolution status.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying condition entry.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing diagnosed patient.
condition_name VARCHAR(150) NOT NULL Standardized condition name (e.g., Ischemic Stroke).
diagnosis_date DATE NULL Date when condition was formally diagnosed.
status VARCHAR(50) NOT NULL, DEFAULT: 'Active' Status: Active, Managed, or Resolved.
created_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when condition was recorded.
TABLE 10: PATIENT ALLERGIES (medical_records_patientallergy)
Tracks verified allergic sensitivities (drug, food, environmental) to prevent adverse medication interactions.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying allergy record.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing allergic patient.
allergen VARCHAR(150) NOT NULL Specific substance causing hypersensitivity (e.g., Penicillin).
reaction VARCHAR(200) NOT NULL, DEFAULT: '' Observed clinical manifestation (e.g., Anaphylaxis, Urticaria).
severity VARCHAR(50) NOT NULL, DEFAULT: 'Moderate' Clinical severity grade: Mild, Moderate, or Severe.
is_active BOOLEAN NOT NULL, DEFAULT: True Indicates if the allergy remains clinically active.
TABLE 11: PATIENT ACTIVE MEDICATIONS (medical_records_patientmedication)
Maintains detailed active medication regimens, therapeutic routes, dosage units, and treatment durations.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying active medication entry.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing medicated patient.
medicine_name VARCHAR(150) NOT NULL Generic or brand name of prescribed drug.
dosage VARCHAR(100) NOT NULL Quantitative dosage value (e.g., 500, 25).
dosage_unit VARCHAR(50) NOT NULL, DEFAULT: 'mg' Measurement unit (e.g., mg, mcg, ml, IU).
frequency VARCHAR(100) NOT NULL Dosage schedule (e.g., TDS, BD, Once daily).
route VARCHAR(50) NOT NULL, DEFAULT: 'Oral' Route (e.g., Oral, Intravenous, Subcutaneous).
prescribing_doctor_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing prescribing doctor.
is_active BOOLEAN NOT NULL, DEFAULT: True Flag indicating if drug is active in patient regimen.
TABLE 12: PRESCRIPTIONS (prescriptions_prescription)
Stores formal prescription orders issued by doctors, including medication lists, duration, and uploaded PDF copies.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying prescription.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing prescribed patient.
prescribing_doctor_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing prescribing physician.
prescription_date DATE NULL Date when prescription was formally issued.
medicines TEXT NOT NULL, DEFAULT: '' Summary list of prescribed medications.
duration VARCHAR(100) NOT NULL, DEFAULT: '7 days' Prescribed therapy duration (e.g., 7 days, Ongoing).
document VARCHAR(100) NULL Storage path for scanned or digital PDF prescription file.
status VARCHAR(50) NOT NULL, DEFAULT: 'Active' Status: Active, Completed, Discontinued.
TABLE 13: MEDICAL CLINICAL RECORDS (medical_records_medicalrecord)
Stores longitudinal electronic health record progress notes and clinical observations authored by attending clinicians.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying clinical note.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key linking note to the patient.
clinician_name VARCHAR(100) NOT NULL Full name of the clinician authoring entry.
notes TEXT NOT NULL Clinical observations, diagnostic notes, and progress logs.
created_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when clinical entry was created.
TABLE 14: PATIENT CONSULTATIONS (medical_records_patientconsultation)
Records formal clinical encounter sessions between physicians and patients, including findings and follow-up schedules.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying consultation.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing examined patient.
doctor_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing consulting physician User account.
consultation_date DATE NOT NULL Date when clinical encounter took place.
reason VARCHAR(255) NOT NULL Chief clinical complaint or consultation objective.
clinical_notes TEXT NOT NULL, DEFAULT: '' Detailed clinical examination findings and diagnosis.
next_consultation_date DATE NULL Recommended date for subsequent clinical review.
TABLE 15: MEDICAL DOCUMENTS (medical_records_medicaldocument)
Stores categorized medical documents, uploaded file links, and optional consultation linkages.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying document record.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing patient who owns document.
uploaded_by_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing user account who uploaded file.
document_type VARCHAR(50) NOT NULL, DEFAULT: 'Other' Type: Blood Test, Scan, Consultation, Prescription, Other.
title VARCHAR(150) NOT NULL Descriptive title of document (e.g., Brain MRI Axial T2).
file VARCHAR(100) NOT NULL Server storage path (medical_documents/).
consultation_id BIGINT FK → medical_records_patientconsultation.id, NULL Optional foreign key linking directly to consultation encounter.

C. IoT and Physiological Monitoring Tables

TABLE 16: WEARABLE DEVICES (devices_wearabledevice)
Maintains physical ESP32-based patient monitoring bands, hardware serial identifiers, MAC addresses, and operational statuses.
Field Name Data Type Constraints Description
serial VARCHAR(20) PK, NOT NULL Unique hardware serial number of wearable device.
mac VARCHAR(30) UNIQUE, NOT NULL Physical Wi-Fi / Bluetooth MAC address of controller.
status VARCHAR(50) NOT NULL, DEFAULT: 'Active' Status: Active, Charging, Maintenance, Decommissioned.
TABLE 17: WEARABLE DEVICE ASSIGNMENTS (devices_deviceassignment)
Maintains strict 1-to-1 operational pairing between an active wearable device and an enrolled patient.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying pairing record.
patient_id VARCHAR(20) FK → patients_patient.id, UNIQUE, NOT NULL One-to-One link to the assigned patient.
device_id VARCHAR(20) FK → devices_wearabledevice.serial, UNIQUE, NOT NULL One-to-One link to the paired wearable device unit.
assigned_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when hardware pairing occurred.
TABLE 18: IoT SENSOR TELEMETRY READINGS (monitoring_sensorreading)
Stores high-frequency automated IoT sensor telemetry transmitted continuously by ESP32 wearable devices.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying telemetry reading.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing monitored patient.
timestamp TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Exact timestamp when telemetry was captured.
heart_rate INTEGER NULL Real-time heart rate from MAX30102 sensor (BPM).
spo2 INTEGER NULL Peripheral blood oxygen saturation from MAX30102 (SpO2 %).
temperature NUMERIC(4, 2) NULL Body temperature from DS18B20 digital sensor (°C).
accel_x, accel_y, accel_z NUMERIC(5, 2) NULL Linear acceleration from MPU6050 accelerometer (m/s²).
gyro_x, gyro_y, gyro_z NUMERIC(5, 2) NULL Angular velocity from MPU6050 gyroscope (deg/sec).
fall_detected BOOLEAN NOT NULL, DEFAULT: False Kinematic threshold trigger indicating a patient fall event.
esp32_connected BOOLEAN NOT NULL, DEFAULT: True Microcontroller heartbeat connectivity status.
esp32_battery INTEGER NULL Remaining battery percentage of wearable unit (0–100%).
TABLE 19: CLINICAL VITAL MEASUREMENTS (medical_records_vitalmeasurement)
Stores episodic and clinical vital sign measurements, distinguishing explicitly between manual bedside data entry and automated readings.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying vital record.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing measured patient.
measurement_time TIMESTAMP WITH TIME ZONE NOT NULL, DEFAULT: now() Exact date and time when measurement was taken.
source VARCHAR(20) NOT NULL, DEFAULT: 'MANUAL' Provenance: MANUAL (bedside entry) or DEVICE (device/ESP32).
entered_by_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing user who entered measurement.
heart_rate, spo2 DOUBLE PRECISION NULL Heart rate (BPM) and oxygen saturation percentage (SpO2 %).
systolic_bp, diastolic_bp INTEGER NULL Systolic and diastolic blood pressure (mmHg).
temperature DOUBLE PRECISION NULL Body temperature in degrees Celsius (°C).
respiratory_rate INTEGER NULL Respiratory rate in breaths per minute.
blood_glucose, weight DOUBLE PRECISION NULL Blood glucose level (mg/dL) and body weight (kg).

D. Alert and Notification Tables

TABLE 20: CLINICAL AND SENSOR ALERTS (alerts_alert)
Captures real-time clinical threshold breaches, physiological emergencies, and AI-generated hazard notifications.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying the alert.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key linking alert to affected patient.
type VARCHAR(50) NOT NULL Type: Heart Rate, SpO2, Fall, Emergency, Temperature.
severity VARCHAR(20) NOT NULL Severity classification: INFO, WARNING, or CRITICAL.
message TEXT NOT NULL Detailed diagnostic description of alert trigger.
status VARCHAR(20) NOT NULL, DEFAULT: 'Active' Status: Active, Acknowledged, or Resolved.
source VARCHAR(50) NOT NULL, DEFAULT: 'System' Origin subsystem: System, AI, Wearable.
TABLE 21: USER NOTIFICATIONS (notifications_notification)
Stores user-specific in-app notifications, system announcements, care-team alerts, and read delivery statuses.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying notification.
user_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing recipient User account.
title VARCHAR(255) NOT NULL Brief headline of the notification.
message TEXT NOT NULL Full body text content of notification.
category VARCHAR(50) NULL Category (e.g., ALERT, MESSAGE, SYSTEM, PRESCRIPTION).
is_read BOOLEAN NOT NULL, DEFAULT: False Read status flag (False = unread, True = read).
timestamp TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when notification was generated.

Maintains dedicated care-team communication channels scoped to individual patients, supporting real-time multi-party chat.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying conversation channel.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key linking conversation to central patient.
status VARCHAR(20) NOT NULL, DEFAULT: 'ACTIVE' Status of conversation thread: ACTIVE or ARCHIVED.
updated_at TIMESTAMP WITH TIME ZONE NOT NULL, Auto-generated Timestamp when conversation was last active.
TABLE 23: CONVERSATION PARTICIPANTS (chat_conversationparticipant)
Represents multi-party membership and role participation in a patient's care-team conversation channel.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying participant record.
conversation_id BIGINT FK → chat_conversation.id, NOT NULL Foreign key referencing conversation channel.
user_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing participant User account.
role VARCHAR(20) NOT NULL Role in chat: patient, doctor, caregiver, family, admin.
is_active BOOLEAN NOT NULL, DEFAULT: True Membership active status flag.
* Composite Unique Constraint: (conversation_id, user_id)
TABLE 24: CARE-TEAM CHAT MESSAGES (chat_message)
Stores individual messages, media attachments, delivery states, read receipts, and clinical emergency priorities.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying chat message.
conversation_id BIGINT FK → chat_conversation.id, NOT NULL Foreign key referencing parent conversation.
sender_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing user who authored message.
message_type VARCHAR(20) NOT NULL, DEFAULT: 'TEXT' Payload format: TEXT, IMAGE, DOCUMENT, VIDEO.
content TEXT NOT NULL, DEFAULT: '' Text content or caption of the message.
attachment VARCHAR(100) NULL Server storage path for uploaded media file.
priority VARCHAR(20) NOT NULL, DEFAULT: 'NORMAL' Priority level: NORMAL, URGENT, or EMERGENCY.
is_emergency BOOLEAN NOT NULL, DEFAULT: False Emergency flag triggering elevated team notifications.

F. AI / Clinical Support Tables

TABLE 25: MEDICATION KNOWLEDGE BASE (ai_services_medicationknowledgebase)
Maintains persistent pharmacological reference records, drug classes, contraindications, precautions, and regulatory formulary references.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying knowledge entry.
generic_name VARCHAR(150) UNIQUE, NOT NULL Standardized pharmacological active substance name.
medication_class VARCHAR(150) NOT NULL Pharmacological / therapeutic drug class.
general_uses TEXT NOT NULL, DEFAULT: '' Standard medical indications and approved clinical uses.
common_precautions TEXT NOT NULL, DEFAULT: '' Clinical warnings and safety precautions.
common_contraindications TEXT NOT NULL, DEFAULT: '' Absolute and relative clinical contraindications.
common_interactions TEXT NOT NULL, DEFAULT: '' Known adverse drug-drug and drug-food interactions.
category VARCHAR(30) NOT NULL, DEFAULT: 'PRESCRIPTION_MEDICINE' Category: GENERAL_INFO, OTC, PRESCRIPTION, RESTRICTED.
source_reference VARCHAR(255) NOT NULL, DEFAULT: 'FDA Label Registry' Official reference citation / formulary authority.
TABLE 26: DOCTOR MEDICATION REVIEW REQUESTS (ai_services_doctormedicationreviewrequest)
Stores AI-assisted medication inquiries requiring formal clinical review and human-in-the-loop sign-off by a physician.
Field Name Data Type Constraints Description
id BIGINT PK, Auto-generated Unique primary key identifying review request.
patient_id VARCHAR(20) FK → patients_patient.id, NOT NULL Foreign key referencing patient under query.
user_id BIGINT FK → accounts_customuser.id, NOT NULL Foreign key referencing user submitting inquiry.
doctor_id BIGINT FK → accounts_customuser.id, NULL Foreign key referencing doctor assigned to review.
medication_name VARCHAR(150) NOT NULL Name of pharmaceutical product under query.
question TEXT NOT NULL Patient/caregiver inquiry regarding safety or dosing.
safety_status VARCHAR(50) NOT NULL, DEFAULT: 'REVIEW_RECOMMENDED' Initial AI-determined safety assessment score/label.
status VARCHAR(30) NOT NULL, DEFAULT: 'PENDING' Workflow status: PENDING, REVIEWED, DECLINED.
doctor_response TEXT NOT NULL, DEFAULT: '' Formal clinical response provided by physician.

G. Supporting Doctor Verification Reference Data

The following tables represent external regulatory registry datasets and hospital affiliation benchmarks used strictly for credential cross-verification and institutional vetting. They are distinct from operational user accounts:
Table Name Model Purpose Verification Functionality
doctors_referencedoctorregistry State Medical Council Gazette Registry Authoritative external benchmark dataset containing official registration numbers, council names, and recognized qualifications to cross-verify doctor onboarding.
doctors_healthfacility Hospital & Health Facility Registry Directory of licensed medical institutions, hospitals, and specialized clinics with state license identifiers.
doctors_doctordisciplinaryrecord Statutory Disciplinary Sanctions Tracks medical council suspension, blacklisting, and sanction orders to flag non-compliant or suspended practitioners.
doctors_referencedoctoraffiliation Reference Institutional Postings Official institutional clinical appointment records linking reference registry doctors to verified hospitals.
doctors_doctorfacilityaffiliation Doctor Hospital Affiliations Operational clinical practice postings logged by registered doctors on the platform.
